## 3. 기호 정의 (논문 3장에 그대로)

| 기호 | 뜻 | 계산 |
| --- | --- | --- |
| F | 한 번에 보는 프레임 수 | 30 (원 논문 모델), 32 (FTCN 클립) |
| D_region[t] | 부위의 시간 불연속 | t−1 과 t 프레임에서 공통인 부위 픽셀의 평균 절대 차이 ÷ 255 |
| D_bg[t] | 배경의 시간 불연속 | 얼굴 상자를 2.0배로 넓혀 제외한 화면 축소판(긴 변 160px)의 평균 절대 차이 ÷ 255 |
| 부위 | 눈, 입, 얼굴 경계, 얼굴 전체 | MediaPipe 랜드마크 478점의 볼록 껍질(눈 +6px, 입 +4px, 경계 띠 ±6px) |
| α | 정규화 강도 | D_bg 1 만큼 변할 때 D_region 이 함께 변하는 양 (최소제곱 추정) |
| R | 정규화된 국소 불연속 | R = D_region − α·D_bg |
| α_t | 학습으로 정하는 정규화 강도 | α_t = α_max · sigmoid(MLP([b_t, b_t − b_{t−1}, d_t])), 프레임마다 스칼라 |
| logit(p) | 점수 비교용 변환 | log(p / (1−p)). 점수가 0·1 에 몰려 있어 그대로 빼면 차이가 묻힘 |

- 영상마다 연속 30프레임, 랜드마크 상자 1.3배를 정사각형으로 잘라 240×240 RGB, 상자 떨림은 창 5의 이동평균으로 완화.

- 얼굴 검출률 FF++ 100%, Celeb-DF 99.99% (실패 1개: `Celeb-real/id27_0005`, 프레임이 1장인 손상 파일).

### 4-2. 전환 벤치마크 생성 (`preprocessing/build_transition_benchmark.py`)

- 기준 영상 140개(real 70 + fake 70: Deepfakes 18, Face2Face 18, FaceSwap 17, NeuralTextures 17), FF++ test 분할.
- 조건 9가지: 대조군, 하드컷, 페이드 8·16·32, 디졸브 8·16·32·64 (단위: 프레임, 25fps 기준 0.32~2.56초).
- 클립 길이 256프레임, 전환 중심 128번 프레임. 전환 구간 밖은 대조군과 **같은 번호의 같은 원본 프레임**이다.
- real 은 real 과, fake 는 **같은 기법의** fake 와 이어 붙여 정답이 바뀌지 않게 했다.
- 전환 계산 (p = 전환 진행도, 0→1):
  - 하드컷: 한 프레임 만에 A → B
  - 디졸브: (1−p)·A + p·B ← face-swap 경계 블렌딩과 같은 형태의 연산
  - 페이드: 앞 절반 A·(1−2p), 뒤 절반 B·(2p−1) (검은 화면을 지나감)
- 합성본과 대조군을 같은 조건으로 재압축(H.264, CRF 23 = FF++ c23 과 동일).

### 4-3. 모델과 학습

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 백본 | XceptionNet (timm `legacy_xception`, ImageNet 가중치) | 원 논문 |

| 입력 | 30프레임 × 240×240 RGB | 원 논문 |
| 최적화 | Adam(β₁ 0.9, β₂ 0.999), lr 1e-4, 배치 2(real 1 + fake 1), 교차 엔트로피 | 원 논문 Table 4 |

### 5-3. 전환이 배경과 얼굴에 주는 영향 — 1,260클립

| 전환 | 배경 D_bg | 얼굴 D_face | 정규화 뒤 남은 증가분 |
| --- | --- | --- | --- |

해석 주의: 이 체크포인트는 Celeb-DF 학습이라 FF++ 에서는 교차 데이터셋 조건이다(대조군에서 fake 를 9%만 탐지).
의미 있는 값은 판정 뒤집힘이 아니라 logit 변화다. **FF++ 로 학습한 B0 로 다시 채점할 예정**(5-7).

출처: `results/benchmark/paper_effect.csv`

## 7. 한계와 예상 질문

| 질문 | 답 |
| --- | --- |
| **전환 증강만으로 되는 것 아닌가?** | 그래서 B1 을 기준선으로 미리 정해 두고 비교한다. B1 과 P 가 같으면 그대로 보고하고, 기여를 "α 해석"과 "전환을 본 적 없는 학습에서의 강건성"으로 옮긴다 |
| 전환을 먼저 검출해 잘라내면 되지 않나? | 그 해법이 실패하는 구간이 바로 문제 구간이다(5-4: 디졸브 32·64 검출률 0%, 민감하게 해도 오검출 34%) |
| 합성한 전환이 실제 영상의 전환과 같은가? | 디졸브·페이드·하드컷은 편집 소프트웨어의 표준 연산을 그대로 구현했다. 다만 실제 방송 영상에는 자막·로고·화면 전환 효과가 함께 오므로, 실제 영상 평가는 후속 과제다 |
| 왜 1 에폭만 학습하나 | 원 논문 Table 4 의 프로토콜(fake 를 한 번씩 모두 사용)을 그대로 따랐다. 기준선과 제안 모델이 같은 조건이므로 비교는 공정하다 |
| 재현 정확도 98%는 너무 높지 않나 | 분할의 인물 중복 때문이다(5-8). 그래서 성능 비교는 FF++ 학습·평가와 교차 데이터셋으로 한다 |
| α 가 상수로 수렴하면? | 그 자체가 결과다. 고정 α 기준선(B3)과 같아진다는 뜻이고, 전환 종류별 α 분포로 보일 수 있다 |
| 학습 증강과 평가 전환이 다르지 않나 | 다르다. 증강은 이미 잘라 둔 얼굴 크롭을 섞어 재압축이 없고 두 얼굴이 중앙 정렬된다. **평가는 항상 실제로 합성·재압축한 벤치마크 클립으로** 하므로 결과가 부풀려지지 않는다 |

**명시할 한계**
1. 전환은 모두 합성이다. 실제 편집 영상에서의 검증은 하지 않았다.
2. 벤치마크의 기준 영상은 FF++ test 140개로, 인물·촬영 조건의 다양성이 제한적이다.
3. 클립 단위 상관 분석은 묶음당 n = 35 로 작다(5-6).
4. 부위 신호는 조작 기법마다 방향이 달라서(5-9), 단일 규칙 기반 탐지에는 쓸 수 없다.
5. 8GB VRAM 제약으로 배치 2, 1 에폭에서만 검증했다.
