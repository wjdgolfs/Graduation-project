## 1단계 원 논문 재현 — Xception + CBAM + Bi-ConvLSTM

이대현·문종섭, "Bidirectional Convolutional LSTM을 이용한 Deepfake 탐지 방법", 정보보호학회논문지 30(6), 2020.
Celeb-DF 논문 방식 분할(학습 real 489 / fake 5,539, 테스트 100 / 100), 1 에폭 63분.

| 지표 | 논문 | 재현 |
| --- | --- | --- |
| 정확도 | 93.5% | **98.0%** (95% 신뢰구간 95.0~99.2) |
| 정밀도 | 98.9% | 97.1% |
| 재현율 | 88.06% | 99.0% |
| F1 | 93.1% | 98.0% |
| AUC | — | 0.997 |

테스트 200개 중 4개 오답(TP 99, FP 3, TN 97, FN 1).

**해석 주의**: 논문 방식 분할은 테스트 인물 53명이 모두 학습에도 나오고, 테스트 fake 100개 중 72개는 원본 real 영상이 학습에 있습니다.
"처음 보는 인물·장면" 평가가 아니므로 점수가 높게 나오기 쉽습니다. 제안 모델과의 비교는 교차 데이터셋 평가(7단계)로 해야 합니다.

원본: `results/paper_bclstm/metrics.csv`, `train_log.csv`, `predictions_epoch_01.csv`

## 2단계 부위 신호 — 조작 기법마다 지문이 다르다

같은 원본 영상에서 만든 fake 와 real 을 짝지어 비교했습니다(배경·인물·조명이 지워지므로 조작 효과만 남습니다).
학습 분할만 사용했고, 괄호 안은 "fake 가 더 큰 장면의 비율"입니다.

| 기법 | 경계/얼굴 비율 | 입/얼굴 비율 | 얼굴 전체 변화량 |
| --- | --- | --- | --- |
| Celeb-DF | 1.07배 (85%) · AUC 0.61 | 0.98배 (43%) | 0.92배 |
| FF++ Face2Face | 1.06배 (73%) · AUC 0.58 | 0.98배 (45%) | 0.88배 |
| FF++ NeuralTextures | 1.02배 (60%) | 0.90배 (27%) | 0.89배 |
| FF++ Deepfakes | 1.02배 (54%) | **0.70배 (9%) · AUC 0.14** | 1.02배 |
| FF++ FaceSwap | **0.93배 (35%)** | 0.98배 (46%) | **1.10배 (68%) · AUC 0.59** |

- "불연속이 크면 fake" 라는 단일 규칙은 성립하지 않습니다. 대부분의 기법에서 합성 얼굴이 오히려 더 매끈합니다.
- 경계/얼굴 비율 가설은 Celeb-DF 와 Face2Face 에서 재현되지만 FaceSwap 에서는 뒤집힙니다.
- 부위 변화량은 배경 변화량(ρ≈0.3)보다 실제 움직임(ρ≈0.5)에 더 크게 좌우됩니다.

재현: `python scripts/summarize_regions.py --dataset ffpp`

## 3단계 전환 벤치마크 — 배경 정규화 효과

FF++ test 분할 영상 140개(real 70 + fake 70)에 전환 9종을 합성한 클립 1,260개.
전환 구간 안과 밖의 평균을 비교했습니다(중앙값).

| 전환 | 배경 D_bg | 얼굴 D_face | 정규화 뒤 남은 증가분 |
| --- | --- | --- | --- |
| 없음(대조군) | 0.9배 | 1.00배 | — |
| 하드컷 | 36.5배 | 9.9배 | 5% |
| 페이드 8 / 16 / 32 | 31.4 / 17.9 / 9.5배 | 7.3 / 4.0 / 2.2배 | 1% / 과보정 / 과보정 |
| 디졸브 8 / 16 | 12.1 / 7.1배 | 4.1 / 2.8배 | 13% / 13% |
| 디졸브 32 / 64 | 4.0 / 2.6배 | 1.8 / 1.4배 | 15% / 16% |

- 전환은 **배경을 얼굴보다 3~4배 크게** 흔듭니다. 배경 정규화가 성립할 조건입니다.
- α(배경 변화 1 만큼당 부위 변화, 최소제곱): 눈 1.00, 입 1.01, 경계 1.26, 얼굴 1.27
- `R = D_face − 1.27 × D_bg` 로 전환이 만든 증가분의 **84~99%** 가 사라집니다.
- 전환이 없는 대조군에서 real/fake 구분력(AUC)은 정규화 전 0.399 → 후 0.423 으로 유지됩니다. 신호를 지운 것이 아닙니다.
- 페이드는 과보정됩니다(검은 화면을 지나며 배경만 유독 크게 변하기 때문). 고정 α 하나로는 모든 전환을 다룰 수 없다는 뜻입니다.

원본: `results/benchmark/clip_stats.csv` · 재현: `python scripts/analyze_benchmark.py`

## 4단계 샷 분할 기준선 — 긴 디졸브는 잡지 못한다

같은 클립 1,260개에 PySceneDetect 를 돌렸습니다. 전환 위치를 알고 있으므로(오차 8프레임 이내를 검출로 인정) 검출률을 정확히 잴 수 있습니다.

| 전환 | 기본 임계값 27 | 민감 15 | 매우 민감 8 |
| --- | --- | --- | --- |
| 하드컷 | 100% | 100% | 99% |
| 페이드 8 / 16 / 32 | 100 / 100 / 99% | 100% | 100 / 100 / 99% |
| 디졸브 8 | 4% | 62% | 100% |
| 디졸브 16 | 1% | 19% | 93% |
| 디졸브 32 | **0%** | 9% | 49% |
| 디졸브 64 | **0%** | 1% | 25% |
| 전환 없는 클립의 오검출 | 4% | 10% | **34%** |

- 하드컷과 페이드는 위치 오차 0프레임으로 잡습니다. "전환을 찾아 잘라내는" 해법이 통합니다.
- 디졸브는 길수록 못 잡습니다. 임계값을 낮춰 억지로 잡으면 멀쩡한 영상의 34% 에서 가짜 경계가 생기고, 그래도 디졸브 64 는 1/4 만 잡힙니다.
- **0단계에서 FTCN 이 오탐을 낸 구간이 바로 디졸브 32·64** 입니다. 기존 해법이 문제 구간에서 실패한다는 직접적인 근거입니다.

원본: `results/benchmark/shot_detection.csv` · 재현: `python scripts/detect_shots_benchmark.py`
