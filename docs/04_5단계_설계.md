# 5단계 설계안: 배경 기준 정규화 모델 (2026-10-02)

원 논문 모델(Xception + CBAM + Bi-ConvLSTM)에 **전역 변화(배경) 분기**를 붙이고,
얼굴 특징에서 전역 성분을 얼마나 뺄지(α)를 **학습으로 정하는** 모델을 만든다.

이 문서는 구현 전에 정해야 할 것(구조, 기준선, 평가, 순서)을 모아 둔 설계안이다.
숫자 근거는 [docs/02_실험결과.md](02_실험결과.md)에 있다.

---

## 1. 측정에서 나온 설계 제약

제안 구조는 취향이 아니라 지금까지 잰 값에서 나왔다.

| 측정 결과 | 설계에 주는 제약 |
| --- | --- |
| 전환은 배경을 얼굴보다 3~4배 크게 흔든다 (3단계) | 배경을 전역 성분의 기준으로 쓸 수 있다 |
| 고정 α = 1.27 은 디졸브는 지우지만 페이드를 과보정한다 (3단계) | α 는 상수일 수 없다 |
| 같은 디졸브 길이 안에서 클립별 D_bg 크기는 FTCN 오탐 크기를 예측하지 못한다 (ρ ≈ 0, 10-02) | α 를 "D_bg 값의 함수"로만 두면 안 된다. **시간 패턴**을 봐야 한다 |
| 손으로 만든 신호만으로는 real/fake 가 거의 안 갈린다 (대조군 AUC 0.42) | 정규화는 학습 모델 **안**에 들어가야 한다. 신호 단독 분류기는 제안 모델이 될 수 없다 |
| 디졸브가 FTCN 오탐을 16/35 → 32/35 로 늘린다 (10-02) | 평가의 1순위 지표는 "전환 구간의 오탐 증가분" |

## 2. 쓸 수 있는 데이터 — 새 전처리 없이 시작할 수 있다

전처리 결과 `.npz` 하나(영상 11,528개)에 이미 들어 있는 것:

| 이름 | 모양 | 쓸 곳 |
| --- | --- | --- |
| `faces` | (30, 240, 240, 3) | 얼굴 분기 입력 (원 논문과 동일) |
| `thumbs` | (30, 120, 160) 흑백 | **전역 분기 입력** (화면 전체 축소판) |
| `smoothed_boxes`, `thumb_scale` | (30, 4), 스칼라 | 썸네일에서 얼굴 영역을 가려 배경만 남기기 |
| `background_diff`, `background_ratio` | (30,) | α 예측기 보조 입력, 배경 신뢰도 판단 |
| `landmarks` | (30, 478, 2) | 부위 마스크(2단계). 부위별 정규화로 확장할 때 |

전역 분기에 쓸 **화면 전체 축소판이 이미 저장돼 있다.** 스칼라 D_bg 만 있는 게 아니므로
"전환이 어떤 모양으로 일어나는지"를 모델이 직접 볼 수 있다. 3절의 α 가 맥락을 보는 근거다.

## 3. 구조

```
얼굴 크롭 [F,240,240,3] ─ Xception → CBAM ─┐
                                           │ F_t [2048,8,8]
                                           ▼
배경 썸네일 [F,120,160] ─ 작은 CNN 4층 ─ b_t [64] ─ W ─ 전역 성분 g_t [2048,1,1]
                            │
                            └─ MLP → α_t = α_max · sigmoid(·)   (프레임마다 스칼라 하나)

정규화:  F̃_t = F_t − α_t · g_t        ← 가설의 R = D_region − α·D_bg 에 대응
         ▼
     Bi-ConvLSTM(은닉 128) → [256,8,8] → FC → real / fake
```

- **α_t 는 프레임마다 스칼라 하나**다. 그래서 학습이 끝난 뒤 α_t 를 시간축에 그려 전환 구간과 겹쳐 볼 수 있다.
  고정 α = 1.27 과 비교해 모델이 무엇을 배웠는지 보여 주는 그림 한 장이 나온다(논문용).
- α_t 의 입력은 전역 분기의 프레임 특징 `b_t`, 그 시간 차분 `b_t − b_{t-1}`, 측정된 `background_diff[t]` 다.
  **값의 크기만 보지 않고 시간 패턴을 본다**(1절 세 번째 제약).
- α_max 는 2.0 으로 둔다(측정된 고정 α 가 1.27 이므로 여유를 둔 상한). sigmoid 로 음수와 과도한 보정을 막는다.
- 정규화 지점을 **Bi-ConvLSTM 입력 단계**로 잡은 이유: 가설이 말하는 불연속은 시간 차이다.
  시간 모듈에 들어가기 전에 프레임마다 전역 성분을 빼면, 시간 모듈은 전역 성분이 제거된 변화만 본다.
  출력 단계에서 한 번 빼는 변형(P-out)은 절제 실험으로 비교한다.

### 전역 분기가 인물을 외우지 못하게

썸네일에서 얼굴 상자를 **2.0배로 넓혀 가린다**(2단계 `background_exclusion_scale` 와 같은 규칙).
`background_ratio < 0.3` 인 영상은 배경이 거의 없어 제외한다(2단계와 같은 기준).

## 4. 학습 데이터와 전환 증강

- **분할**: FF++ 공식 분할 (train real 720 / fake 2,880, val 140 / 560, test 140 / 560).
  1단계는 Celeb-DF 였지만 전환 벤치마크가 FF++ test 라서 FF++ 로 맞춘다.
- **전환 증강**: 학습 중에 두 영상의 `faces` 와 `thumbs` 를 프레임 단위로 블렌딩해 디졸브·페이드·하드컷을 만든다.
  - **같은 라벨끼리만** 붙인다(real+real, fake+fake 는 같은 기법끼리). 정답이 바뀌지 않는다. 3단계 벤치마크와 같은 규칙이다.
  - 입력이 30프레임이므로 디졸브 길이는 **8~24** 로 둔다(64프레임 디졸브는 윈도 전체가 전환이라 "전환 밖"이 없다).
  - 증강 비율 50%. 전환 없는 입력도 계속 봐야 전환 없는 성능이 유지된다.
- **배치**: real 1 + fake 1 (논문 Table 4 방식, `utils/face_clips.py` 에 구현돼 있음).

## 5. 비교할 기준선 — 심사에서 반드시 물어볼 것

| 이름 | 내용 | 왜 필요한가 |
| --- | --- | --- |
| B0 | 원 논문 모델 그대로 | 출발점. 전환에 약하다는 것을 같은 모델에서 보여야 한다 |
| **B1** | 원 논문 모델 + 전환 증강만 | **"증강만으로 되는 거 아니냐"에 대한 답.** 제안 구조가 이걸 못 이기면 기여가 없다 |
| B2 | 샷 분할로 전환을 찾아 잘라내기 | 실무 표준 해법. 4단계에서 디졸브 32·64 를 기본 설정에서 0% 잡는다는 결과가 이미 있다 |
| B3 | 고정 α = 1.27 정규화 | 학습이 정말 필요한지. 페이드 과보정이 재현되어야 한다 |
| P | 제안 모델 (학습되는 α_t) | |
| P-out | 정규화를 Bi-ConvLSTM 출력에서 하는 변형 | 정규화 지점이 중요한지(절제 실험) |

**B1 이 가장 중요한 비교다.** B1 과 P 가 비슷하게 나오면 "구조 없이 증강으로 충분하다"가 결론이 되고,
그것도 보고할 가치가 있는 결과다(기여는 작아진다). 미리 정해 두고 정직하게 보고한다.

## 6. 평가 프로토콜

| 순위 | 지표 | 기준 |
| --- | --- | --- |
| 1 | **전환 구간의 오탐 증가분** — 벤치마크 real 클립에서 대조군 대비 가짜 판정 비율 증가 | P 가 B0·B1 보다 유의하게 작아야 한다 (짝지은 검정) |
| 2 | **전환 없는 성능** — FF++ test 140+560 의 정확도·AUC | B0 보다 떨어지면 안 된다. 떨어지면 정규화가 신호까지 지운 것이다 |
| 3 | **일반성** — Celeb-DF test 교차 평가 (7단계) | B0 와 비교. 전환 강건성이 일반 성능을 깎지 않는지 |
| 보조 | α_t 분포 — 전환 종류·구간별 | 전환 구간에서 α 가 커지는지. 모델이 무엇을 배웠는지 보여 주는 그림 |

벤치마크 채점은 전환 중심 **30프레임 윈도**로 자른다(모델 입력이 30프레임).
FTCN(32프레임 클립 단위)과는 보는 범위가 달라서 숫자를 직접 비교하지 않고, 각 모델의 대조군 대비 변화량으로 비교한다.

## 7. 구현 순서와 예상 시간

가장 먼저 **결정이 필요 없고 결과가 바로 나오는 것**부터 한다.

| | 작업 | 시간 | 산출물 |
| --- | --- | --- | --- |
| 1 | 벤치마크 평가 하네스: 클립 → 전환 중심 30프레임 얼굴 전처리 + 모델 채점 + 표 | 코드 2시간, 전처리 1시간(CPU) | **6단계 결과**(원 논문 모델도 전환에 속는지) |
| 2 | 전환 증강 데이터 로더 + 테스트 | **완료 2026-10-02** (`utils/transition_augment.py`, 테스트 8개) | B1 학습 가능 |
| 3 | B0·B1 학습 (FF++) | 1 에폭 각 ~1시간 | 기준선 2개 |
| 4 | 전역 분기 + α 게이트 구현 + 모양 테스트 | **완료 2026-10-02** (`models/normalized_bclstm.py`, 테스트 8개) | 학습 스크립트 연결만 남음 |
| 5 | P·P-out·B3 학습 | ~1.2시간 × 3 | 제안 모델 |
| 6 | 전체 평가와 표·그림 정리 | 2~3시간 | 논문 결과 절 |

실제로 재 본 값 (2026-10-02, 구현 뒤 3스텝 시험):
파라미터 41.6M 중 추가된 부분은 0.20M(0.5%), VRAM 최대 2.45GiB, 스텝당 0.55초(배치 2, gradient checkpointing).
썸네일에서 얼굴 자리로 가려지는 비율은 평균 21.7% 였다. 1 에폭(2,880스텝)은 **30~40분** 으로 보면 된다.

GPU 작업 합계 6~8시간, 코드 작업 반나절. **학습 중에는 CPU 전처리를 함께 돌리지 않는다**(블루스크린 이력, `docs/00_setup_checklist.md` 4-2).

## 8. 위험과 대비

| 위험 | 대비 |
| --- | --- |
| B1(증강만)이 제안 모델과 같은 성능 | 그대로 보고한다. 기여를 α 해석(무엇을 배웠는지)과 "전환을 본 적 없는 학습에서의 강건성"으로 옮긴다 |
| 전역 분기가 배경 대신 인물·화질을 외운다 | 얼굴 상자 2.0배 가리기, `background_ratio < 0.3` 제외, 전역 분기만으로 분류해 보는 확인 실험 |
| 30프레임 안에 긴 전환이 들어가지 않는다 | 증강 길이 8~24, 평가는 전환 중심 30프레임 윈도. 긴 전환 평가는 FTCN(32프레임 클립) 쪽 결과로 보완 |
| FF++ 는 기법 4종이 섞여 Celeb-DF 보다 어렵다 | B0 가 문헌 수준인지 먼저 확인하고, 1단계 Celeb-DF 98.0% 는 상한선 참고로만 쓴다 |
| α 가 전환과 무관하게 상수로 수렴 | α_t 를 전환 구간/바깥으로 나눠 확인. 상수로 수렴하면 B3(고정 α)와 같아지므로 그 자체가 결과다 |
